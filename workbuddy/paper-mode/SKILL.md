# 论文模式（paper-mode）· WorkBuddy 版

> **运行说明**：本文件是为 **WorkBuddy（腾讯办公智能体）** 适配的技能版本，按 WorkBuddy 技能约定（`~/.workbuddy/skills/<name>/SKILL.md`）编写。原版技能为 DeepSeek Harness 专用（见 GitHub 仓库 markbignews/cn-thesis-aigc-detector）；本版已在格式与流程上做平台适配，但**未经真实 WorkBuddy 运行环境实测**，使用中发现偏差请按本文件末尾「能力协商」自行调整。

把中文学术论文的 AI/AIGC 痕迹检查与降率改写做成一个闭环：**引述核查 → 检测估算 → 修改意见 → 确认改写 → 复查循环**，直到全文估算 AI 率 ≤ 用户指定的目标比例（默认 ≤10%）。

## 适用场景

- 用户提供中文学术论文（本科/硕博论文、期刊稿）全文或段落，要求**检测 AI 生成痕迹 / 估算 AI 率 / AIGC 率**；
- 要求**逐段给出修改意见**，或**改写**让文本不像 AI 写的；
- 输入形态：粘贴文本、或工作区/上传的 Word(.docx)/PDF 等文稿。

## 快速开始（示例用法）

直接向 WorkBuddy 描述需求即可自动匹配本技能，例如：

- "帮我检查这篇论文的 AI 率，目标降到 10% 以下"
- "下面这段太像 AI 写的了，帮我改得更自然：<粘贴段落>"
- "读一下工作区的 paper.docx，先出 AI 痕迹检测报告和修改意见，我确认后再改"

收到文本后按「工作流」执行；首次交付先给估算报告与修改意见清单，用户确认后才逐段改写，避免一次大改全文。

## 核心约束（红线，违反视为失败）

1. **估算 ≠ 官方结果**：所有 AI 率数字都是基于知网 AIGC 检测**语言特征**的估算，不是知网/维普/Turnitin 官方检测；每次输出估算必须附这句声明，并建议用户上官方平台实测。
2. **不得编造**：不改写出的数据、实验、案例、引用；没有证据支撑时宁可弱化语气、补充边界。引述有疑必须向用户明示，不能靠改写掩盖。
3. **必须保留**：事实、数字、术语、公式、图表引用、引用编号、结论方向、学术语体（不口语化）。
4. **计划优先**：检测/改写前先给用户计划（目标比例、高危段落清单、策略、预期改动），**用户确认后再动手**，绝不未经确认一次性大改全文。
5. **目标 <10% 要如实提示**：约 10% 是中文学术语体实用下限，再低明显损伤学术性；若用户坚持则照做并告知风险。
6. **合规边界**：仅用于投稿/查重前的自查与语言润色，不用于规避官方检测、掩盖代写或学术不端；不得教唆用户伪造"人写"证据。

## 工作流

按用户输入整体执行；长文（>3000 字）先出全文报告与高危段落清单，经用户选定后再逐批改写。

### 阶段 0：引述/引用可靠性核查（先于检测）

1. 提取全文所有引述并编号（作者+年份、文献题名、引文、数据/图表来源、URL 等）。
2. 若宿主提供联网检索能力：逐条检索核验来源是否真实、内容是否支撑主张、数据有无出处。
3. 汇总判定：✅ 靠谱 / ⚠️ 需核实 / ❌ 疑似捏造；⚠️ 与 ❌ 必须向用户明示并给处理建议（替换为真实来源；否则删除、弱化或补边界——**不得编造替身来源**）。
4. 若宿主**无**联网检索能力：在报告开头明确标注"引述未联网核验"，请用户自行核对。
5. 核查结果作为报告第一部分，不得跳过。

### 阶段 A：检测与估算（输出"AI 率检测报告"）

1. 获取全文文本：粘贴文本直接使用；文档由宿主读取（见「能力协商」）。
2. 逐段（每 150–450 字合并一块）对照「判定信号速查」检查，判定每块：
   - **风险等级**：高（AI 特征强）/ 中（疑似）/ 低（更像人写）；
   - **命中的高危特征**（如：句长节奏均匀 L1、连接词重叠 L4、模板套话 L5）；
   - **缓和信号**（引用编号、数据、图表号、领域专名、"较为/通常/往往"等留余地学术语——这些是人写特征）。
3. 报告格式：
   ```
   ### AI 率检测报告（估算）
   - 总字符数、处理块数、输入形态（粘贴/docx/pdf）
   - 逐块：块号 | 风险等级 | 命中特征 | 缓和信号 | 估算区间
   - 估算总 AI 率：约 X%（高=1.0、中=0.5 加权 × 字符占比）
   - 明确：本估算非知网/维普官方结果，建议官方实测
   - 优先级最高的待改段落清单
   ```
4. 摘要/Abstract、纯文献罗列段、方法学固定表述结构化程度高：优先提示但不作为主要改写目标。

### 阶段 B：修改意见（先方案，确认后改）

1. 问清目标比例（默认 ≤10%）与范围（只改标红段还是全文过一遍）。
2. 列修改意见清单，不改写原文：段落位置 → 原句摘录 → 命中问题 → 具体改法（≤3 条）→ 不改的部分。
3. 用户确认后进入改写。

### 阶段 C：改写与复查循环（直到达标）

改写按「改写规则」执行；每轮后过「硬约束自检表」，再重新估算 AI 率并如实汇报新旧对比；未达标只定点改当前最红的段落，循环直到 ≤ 目标比例。

### 阶段 D：交付

- 逐段以"原文 → 改写文 → 改动说明"呈现。
- 导出：若宿主能生成 Word/文档，只做**定稿原样导出**（逐字保留，不做任何改写）；不能则交付 Markdown/文本，请用户自行粘贴进 Word。
- 提醒用户上知网等官方平台实测，把仍标红段落回传做二次精修。

## 判定信号速查

### 五维信号（L1–L5）

| 维度 | AI 特征 | 改法 |
|---|---|---|
| L1 句法节奏 | 句长集中于 20–35 字、标准差小、节奏均匀 | 混入 10–18 字短句与 40+ 字长句 |
| L2 信息密度 | 每段密度均匀、段结构全等 | 高密度论证段/低密度铺陈段交替 |
| L3 术语句法位置 | 术语总在主语位（"XX 是/具有…"） | 术语不动，移到宾语/状语/定语或指代复指 |
| L4 连接词重叠 | 同段同功能连接词 ≥2 个 | 同功能只留 1 个，其余删或用标点承接 |
| L5 模板段 | 工整排比、抽象名词链、段尾元话语收束、泛化套话 | 拆排比为长短句递进；删套话与段末收束句 |

### 必避 AI 高频词

此外、与此同时、综上所述、值得注意的是、具有显著优势、具有重要意义、不仅…而且…、其一…其二…其三…、深刻揭示、不可或缺、综合运用、有效解决、充分说明、进一步（滥用）。

### 修复策略（有效做法摘要）

1. 破三段式：首先/其次/最后 → 自然过渡；
2. 去模板起笔：删"基于/在…方面"等公式化段首，现象描述先行；
3. 40+ 字长句在转折处断开；
4. 注入具体性：抽象概括换数据/细节；无数据则弱化语气补边界；
5. 长短句交替变化节奏；
6. 删连接词/套话与段末总结句；
7. 三元并列改不对称（重要的多说，次要的简说，可只写两项）；
8. 无出处的"专家认为/研究表明"→ 给具体来源或改为本文判断；
9. 删填充短语（"值得注意的是，数据显示"→"数据显示"）；
10. 注入作者视角：承认局限、表达意外、留判断（"笔者认为…"）；
11. 泛化结论改可检验推论（"具有重要意义"→ 可验证命题）。

> 无效做法：换同义词（检测器抓句法节奏）、全面口语化、删光"较为/往往/可能"等学术缓和语、给术语加引号制造距离、为降率篡改数据、一次大改全文导致密度全线下降。

### 硬约束自检表

| 约束项 | 上限 |
|---|---|
| AI 高频词 | 每段 ≤2 |
| 段末总结套句（"此案例印证了/由此可见"） | 全文 ≤1 |
| 整齐三元/四元并列 | 每段 ≤1 |
| "基于/依据XX理论"起笔段落 | ≤20% 段落 |
| 泛化结尾（"具有重要意义/前景广阔"） | 全文 0 |
| 模糊归因（"专家认为"无出处） | 全文 0 |

### 噪声预算（防过度清洁）

每千字保留 2–3 处轻微 AI 特征作自然噪声（如两项并列、程度较轻的过渡词全文 ≤1 处）；不要把所有段落改成同一风格。

细节与完整方法论见本技能目录 `references/aigc_signals_zh.md`（判定唯一依据）与 `docs/thesis_workflow_zh.md`（流程文档），需要时读取。

## 能力协商（按宿主能力自动降级，勿编造能力）

- **文件输入**：宿主能读工作区/上传文档就直接读；否则请用户粘贴文本，或把文件放进工作目录让宿主读取；实在读不了就如实说明。
- **文档解析**：若宿主环境可运行 `python3` 且本技能目录含 `scripts/`，优先用脚本提取文本——docx/pptx/xlsx 用 `scripts/office_extract.py <文件> [out.txt]`，docx 结构化原文用 `scripts/docx_extract.py <docx> [out.txt]`，PDF 文字版用 `scripts/pdf_to_text.py <paper.pdf> [out.txt]`（需 pypdf 或 pdftotext），公式/图表/扫描件可用 `scripts/pdf_to_images.swift <pdf> <outdir> [width]` 转 PNG（macOS）。不可运行脚本时依赖宿主自带解析。
- **信号扫描脚本**：`scripts/ai_signal.py <文本或docx>` 可作确定性辅助扫描（150–450 字分块输出句长节奏/连接词/套话等证据）；无 python 环境时按上方速查表人工逐块判定即可（脚本只出证据，不替代判定）。
- **定稿导出**：`scripts/docx_write.py <定稿.txt> <输出.docx>` 可把定稿**逐字**装回 .docx（支持 `#` 标题与 `**加粗**`）；导出后可用 `office_extract.py` 回读复核。
- **联网检索**：有则用于阶段 0 引述核验；没有则明示"未联网核验"。
- **子代理/多会话**：宿主支持多 agent 时，复查轮尽量由不携带改写记录的新会话独立再估算；不支持时，可建议用户把改写后文本**另开新会话**让第二位 AI 盲评，避免"改写着自测"的乐观偏差。
- **文档导出**：宿主能生成 Word 才导出 .docx（仅原样装订）；否则交付文本由用户自贴。
